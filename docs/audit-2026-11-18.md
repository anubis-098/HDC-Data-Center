# Project audit — 18 November 2026

Scope: HDC Data Center, its shared account and Store integration, Container Loading, and Tote Tracker. This is a source and automated-test audit of the local repositories. It does not establish that every possible bug has been eliminated.

## Confirmed bugs corrected

| Impact | Finding | Correction |
| --- | --- | --- |
| Medium | Container Loading API requests had no deadline. A stalled network request could leave loading or upload controls blocked indefinitely. | Added 30-second deadlines for normal requests, 90 seconds for photo uploads, caller cancellation, timer cleanup, and an uncertain-result message advising the operator to check saved status before retrying. |
| Medium | Data Center could accept more than 10,000 Stores through cumulative imports or manual creation, although both consumers reject larger snapshots. | Enforced the total dataset limit for creation, import preview, atomic import confirmation and local CLI import. Existing records can still be updated at capacity. |
| Medium | A valid dataset of 10,000 Stores with category memberships can exceed the sync client's 5 MB response ceiling. | Raised the bounded Store response limit to 25 MB; regression test exercises 10,000 Stores with all 15 memberships. The Excel upload limit remains 5 MB. |
| Low | JSON `null` produced HTTP 500 on login and other endpoints; arrays and primitive JSON were not consistently rejected. | Require a JSON object and return HTTP 422 before accessing request fields. Malformed JSON still returns HTTP 400. |
| Low | Invalid percent encoding in Store URLs could throw a URIError and return HTTP 500. | Return HTTP 400 for malformed URL encoding. |
| Low | Container Loading's dashboard search placeholder contained literal question marks. | Restored the Thai vehicle registration label. |

The request-shape, URL and Store-capacity cases were reproduced with failing regression tests before applying the fixes. No production Store data was created, deleted or imported during the audit.
